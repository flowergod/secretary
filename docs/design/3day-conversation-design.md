# 智能秘书 · 3日对话流产品设计

**产品名称**: 语义秘书 (Semantic Secretary)
**版本**: v2.0
**设计人**: 产品设计团队
**最后更新**: 2026-05-06

---

## 一、产品定位与用户画像

### 1.1 产品定位

语义秘书是一款基于自然语言理解的日程管理 AI 助手，能够：
- 通过长连接实时响应用户指令
- 理解模糊、自然的语言表达
- 主动管理上下文语境
- 自动协调多平台日历（飞书 + iCloud）

### 1.2 目标用户画像

**李明** | 38岁 | 科技创业公司联合创始人

**基本信息**:
- 已婚，育有一儿一女（儿子7岁，女儿4岁）
- 每天工作10-12小时，经常出差
- 使用飞书进行工作沟通，iCloud 管理个人日程
- 习惯用手机语音输入，碎片化时间管理

**痛点**:
1. 会议太多，时间碎片化，记不住所有安排
2. 经常临时变更，需要快速修改日程
3. 孩子的学校活动需要特别提醒
4. 工作和生活边界模糊，需要快速切换

## 三、第一日：标准工作日

### 场景 1：早安查询

```
【7:30】
李明: 早上好，今天有什么安排？

秘书: ☀️ 早！李明，今天（5月11日 周一）的日程如下：

📅 管理层周会
   ⏰ 09:00 - 10:00
   📍 会议室A
   状态: 已确认

📅 产品进度汇报
   ⏰ 10:30 - 11:30
   📍 会议室B
   状态: 已确认

📅 投资人电话会议
   ⏰ 14:00 - 15:00
   📍 线上
   状态: 已确认

📅 产品评审会
   ⏰ 17:00 - 18:00
   📍 会议室A
   状态: 已确认

💡 共4项日程，上午较忙，下午有空档

另有待办任务 3 项未完成
```

**设计要点**:
- 起床后第一句话，简洁明了
- 自动归类整理，时间线清晰
- 识别工作节奏，给出建议
- 待办任务单独列出，不干扰主日程

### 场景 2：快速添加任务

```
【7:45】
李明: 提醒我今天下班去超市买牛奶和鸡蛋

秘书: ✅ 已添加提醒！

🛒 任务: 下班去超市买牛奶和鸡蛋
   ⏰ 提醒时间: 18:00（下班时间）
   📍 建议地点: 盒马鲜生（公司附近）

是否需要设置具体提醒时间？
```

**设计要点**:
- 识别为「提醒」而非「会议」，自动归类
- 推断下班时间 18:00 作为提醒时间
- 结合位置智能推荐

### 场景 4：会议前提醒 + 上下文延续

```
【10:55 会议前5分钟】

   📍 管理层周会将在 11:05 结束
```

- 智能识别「现在」= 当前正在进行的会议
- 主动关联相关文档
- 会议前主动准备

## 六、对话交互模式总结

### 6.1 响应策略矩阵

| 场景类型 | 响应策略 | 示例 |
|---------|---------|------|
| 早安查询 | 结构化展示 + 关键提醒 | 「今天3件事:...」 |
| 快速添加 | 确认 + 执行 + 关联建议 | 「已添加，需要设置提醒吗？」 |
| 变更请求 | 可行性分析 + 方案选择 | 「A/B/C三个方案可选」 |
| 会议中打断 | 无声处理 + 稍后确认 | 「[无声] 已记录」 |
| 模糊表达 | 主动确认 + 上下文补全 | 「你说的XX是指...？」 |
| 家庭时间 | 简化信息 + 温馨提醒 | 「💡 建议早点回家陪孩子」 |

### 6.2 上下文维持策略

1. **会话级上下文**: 同一对话中识别指代（「那个会议」「他」）
2. **日程级上下文**: 跨日程关联（「上次说的」「改期后」）
3. **用户画像上下文**: 长期偏好学习（「你通常喜欢...」）

### 6.3 情绪识别与响应

| 情绪信号 | 响应方式 |
|---------|---------|
| 着急/忙碌 | 简洁优先，增值服务后置 |
| 轻松/闲聊 | 适当幽默，信息密度降低 |
| 疲惫/压力 | 主动建议休息，保护时间 |
| 成功/开心 | 正向反馈，成就感强化 |

## 七、技术实现要点

### 7.1 关键接口设计

```
POST /api/semantic/understand
POST /api/semantic/confirm
GET  /api/semantic/context/:contextId
WS   /ws/semantic
```

### 7.2 意图分类优先级

1. **强意图词**: 创建/删除/修改/取消 → 直接执行
2. **弱意图词**: 看看/有没有/怎么样 → 查询+展示
3. **模糊表达**: 嗯/哦/算了 → 上下文推断

### 7.3 确认时机

- 置信度 < 0.7 → 必须确认
- 涉及删除/取消 → 必须确认
- 时间冲突 → 必须确认
- 新增跨天日程 → 建议确认

   - 临时解决：添加 uncaughtException 全局处理器捕获 EADDRINUSE
   - 根因：疑似 Node.js 24.x 的模块缓存或事件循环问题
   - 修复位置：`src/server.ts`
